## P0 — блокирующие

### P0-1. Poker: неверный кикер при трёх парах и при каре + паре → неправильный победитель банка
`panorama/scripts/rules/poker.js:102,108` + `firstOther`/`firstOtherPair` (`:115-116`)

```js
if (c0[0] === 4) return [7, c0[1], firstOther(vals, c0[1])];
...
if (c0[0] === 2 && c1 && c1[0] === 2) return [2, c0[1], c1[1], firstOtherPair(vals, c0[1], c1[1])];
```

`vals` строится из `groups`, отсортированных **сначала по count, потом по value** (`:96`). Поэтому третья пара / вторая пара стоит в `vals` **раньше** одиночных карт, и `firstOther*` возвращает её ранг, а не старшего кикера. Проверено:

| ситуация | движок | правильно |
|---|---|---|
| `AS AH KS KH 2S 2H QC` | `[2,14,13,2]` | `[2,14,13,12]` |
| `2S 2H 2D 2C 3S 3H AC` | `[7,2,3]` | `[7,2,14]` |

Разворачивает реальные банки:
- борд `AS AH KS KH 9C`; hero `2S 2H` → `[2,14,13,2]`, villain `5S 3H` → `[2,14,13,9]`. Должен быть **split**, движок отдаёт весь банк villain'у.
- борд `6S 6H 6D 6C KC`; hero `JS TH` → `[7,6,13]`, villain `QS QH` → `[7,6,12]`. Должен быть **split**, hero забирает всё.

Фикс: кикер выбирать по **отсортированным по значению** одиночным картам, а не по `vals`.

### P0-2. Poker: рука зависает намертво, если открывающий действие сит ушёл в all-in блайндом
`panorama/scripts/rules/poker.js:208-215` (`newHand`) + `:228` (`legalActions`) + `:293-301` (`advance`)

```js
putIn(st, sbSeat, sb);            // ставит all-in, если stack <= sb
...
st.toAct = (activeSeatCount(st) === 2) ? sbSeat : nextToAct(st, bbSeat);
```

`newHand` присваивает `toAct = sbSeat` в heads-up **без проверки `allIn`**. `legalActions` для all-in сита возвращает всё `false` (`:228`), `applyAction` отклоняет fold/check/call/raise, `advance` никогда не вызывается → `street` навсегда `"preflop"`.

Минимальный репро: `newHand(2, 0, [3,100], 5, 10, 7)` → `toAct=0`, `allIn=[true,false]`, `legalActions(0)` полностью `false`, все три действия возвращают `false`, `street` остаётся `preflop`.

Достижимо в живой игре: воспроизвёл циклом ботов, **17 из 200 столов** упираются в зависшую руку. Также 13 комбинаций стеков для 3–4 сит.

Последствия: offline — `afterAdvance` шедулит `botStep`, тот получает `false` от `applyAction` и повторно фолдит → стол мёртв. Online — `pokerAct` на сервере отдаёт `code 2`, никто не может действовать, лобби не завершается.

Фикс: в конце `newHand` (и в `nextStreet`) прогнать `toAct` через `nextToAct`, если выбранный сит `allIn`/`stacks===0`, и если `nextToAct` вернул `-1` — сразу `runout(st)`.

**Тестовая слепая зона:** `mg_poker_test.js:154` играет всего **40 рук на стол** и на 160-й строке при отклонённом действии просто помечает `allTerminated=false`, но `guard++<1000` выходит из цикла, и тест всё равно проходит.

### P0-3. Connect Four: eval бота считается с точки зрения `me`, а не текущего игрока → бот играет **против себя**
`panorama/scripts/rules/connectfour.js:160-162`

```js
if (lastR >= 0 && winsAt(b, lastR, lastC, lastV))
    return lastV === me ? -(100000 + depth) : (100000 + depth);
if (depth === 0) return evalBoard(b, me);
```

Это negamax (`val = -negamax(...)` на `:171`), значит оба возврата обязаны быть **относительно `player`**. С фиксированным `me` знак чередуется вместе с глубиной.

Проверено:
- на пустой доске `cfBotMove(b,1)` возвращает **колонку 0**; референсный negamax — **колонку 3**;
- head-to-head, 40 партий: **shipped 0 : 40 fix**, 0 ничьих.

Тесты этого не ловят: `mg_connectfour_test.js` проверяет только «ход легален» + два тактических шортката, которые не идут через `negamax`. `mg_parity_test.js:120` сравнивает client vs server — оба одинаково сломаны.

Фикс — две строки:
```js
if (lastR >= 0 && winsAt(b, lastR, lastC, lastV)) return -(100000 + depth);
if (depth === 0) return evalBoard(b, player);
```
Перф: 15 ms на пустой доске, 6 ms в мидгейме.

## P1 — реальные баги

### P1-1. Checkers: игра объявляется законченной, когда у соперника нет ходов, хотя ход ещё не его
`panorama/scripts/mg_checkers.js:1146-1155`

```js
function checkEnd() {
    var opp = (myColor === WHITE ? BLACK : WHITE);   // ← dead var
    if (!hasAnyMove(board, WHITE)) { finish(BLACK); return; }
    if (!hasAnyMove(board, BLACK)) { finish(WHITE); return; }
```

Проверяются **оба** цвета независимо от `turn`. Канон draughts: проигрывает тот, кто не может ходить **на своём ходу**.

Проверено случайным self-play (4000 партий): **140 досрочных game-over**.
> Примечание при исправлении: перепроверено — 48/4000 (порядок тот же, баг подтверждён).

Фикс: `if (!hasAnyMove(board, turn)) finish(turn === WHITE ? BLACK : WHITE);` плюс проверки на 0 фигур.

### P1-2. Chess: нет ни одного правила ничьей кроме пата → мёртвая партия не заканчивается никогда
`panorama/scripts/rules/chess.js:207-210`, `initialChessState():54`

Нет полусчётчика ходов, нет истории позиций → **нет правила 50 ходов, нет троекратного повторения, нет недостаточного материала**. Проверено:
- `K vs K` → `"ongoing"`; `K+B vs K` → `"ongoing"`;
- бот-против-бота из `K vs K`: **400 полуходов, ни одного терминала**.

В онлайне единственный выход — таймаут, а при `timeControl = 0` (дефолт) партия не заканчивается вообще.

### P1-3. Poker: неполный all-in raise переоткрывает действие уже уравнявшим игрокам
`panorama/scripts/rules/poker.js:266-271`

Комментарий на `:266-267` явно описывает нужное поведение, но `resetActedExcept` вызывается всегда. Проверено: после неполного шова `acted=[false,false,true]`, `legalActions(0).canRaise === true`. По стандартному NLHE seat 0 может только call/fold.

### P1-4. Chess: `rejectAndResync` не сбрасывает `history` → список ходов дублируется после отказа сервера
`panorama/scripts/mg_chess.js:803-811` vs `panorama/scripts/mg_checkers.js:1047-1058`

Checkers-версия явно делает `history = []; reviewIndex = null;`. В chess-копии этих двух строк нет. Копипаста, которая разъехалась.

### P1-5. Wordle: одна и та же answer на всю сессию модуля
`panorama/scripts/mg_wordle.js:70,100-102` — `(day + gamesStarted * 37)`. В двух разных сессиях в один день первое слово **всегда одинаковое**.

### [P0] `mg_server_test.js`: флейк в assert'е БЕЗОПАСНОСТИ — 6.25% ложных провалов, root cause в тесте
`tools/mg_server_test.js:311-316`
```js
var tamperedSession = sessionMatch[1].substring(0, sessionMatch[1].length - 1) +
    (sessionMatch[1].endsWith("A") ? "B" : "A");
```
HMAC-SHA256 = 32 байта → base64url ровно 43 символа. 43-й символ несёт **только 4 значащих бита**, младшие 2 бита — padding. `base64UrlBytes()` (`worker.core.js:230`) их игнорирует, поэтому подмена `A`→`B` даёт байт-в-байт **тот же HMAC**. Ровно 1/16 подписей.

Проверено: 6/30 прогонов упали. Изолированный расчёт: `6242/100000 = 6.24%`. Провалы кластеризуются, потому что payload содержит `exp` в секундах. **Сам worker корректен — дефект в тесте.**

Фикс: портить payload, а не хвост подписи: `var tamperedSession = "x" + sessionMatch[1].slice(1);`

### [P0] `strip_comments.js` ломает файлы: regex-литерал после ключевого слова + `/*` внутри CSS-строк
`tools/strip_comments.js:41-46`
```js
return "(,=:[!&|?{};+-*%^~<>".indexOf(c) !== -1;
```
Эвристика смотрит только на предыдущий символ, без учёта ключевых слов. После `return`, `case`, `typeof`, `in`, `new` предыдущий символ — буква → regex не распознан, его `/` съедается как начало комментария.

Проверено. Вход парсится, выход — нет:
```js
function a(s){ return /"/.test(s); }
var m = "a // b";
```
→ `SyntaxError: Invalid or unexpected token`.

Второй дефект — CSS: `stripBlock` не знает про строки: `url("a/*b*/c.png")` → `url("ac.png")`.

Текущее дерево пока выживает (прогнал stripper на копии, `node --check` по всем 22 файлам — чисто). Но `mg_pixelbattle.js:31` — `return /^\d{5,12}$/.test(text)` — уже в одном символе от подрыва.

Фикс: список keyword'ов в `regexAllowed()` (готовый образец — `isRegexPrefixContext()` в `QOLLOCK/scripts/minify_panorama_js.js:57-60`); учёт строк в CSS `stripBlock`; **self-validate** через `vm.Script` перед записью.
